Building a Cowrie SSH Honeypot

Linux · SSH · Honeypots

I've been working on my cybersecurity homelab, and one of the projects I'm building is an SSH honeypot using Cowrie. I want to understand what happens when someone connects, what gets logged, and how I can use that information to investigate activity.

My setup

  • Windows PC
  • Oracle VirtualBox
  • Ubuntu Linux VM
  • Cowrie SSH honeypot
  • TCP port 2222 for testing

I'm keeping everything in a virtual lab so I can test things in a controlled environment without exposing the honeypot to the public internet.

Getting Cowrie running

I installed the prerequisites, cloned the official Cowrie repository, set up a Python virtual environment, and installed the dependencies. After configuring and starting Cowrie, I checked that the service was running.

I then connected over SSH using the local loopback address on port 2222 and tried a few harmless commands. This was my first test to make sure the connection worked and Cowrie was recording the session.

Checking the logs

After the test session, I inspected Cowrie's JSON event log at var/log/cowrie/cowrie.json. The log recorded the connection, simulated successful login, commands entered, and session closure. This helped me understand how a honeypot turns an interactive session into structured security events that can be investigated later.

The logs showed me how Cowrie records an SSH session from the initial connection to the session closing. I identified the source IP (127.0.0.1), the simulated successful login as root, and commands i used which were whoami, ls, and uname -a. Also Cowrie recorded a mistyped command as a failed event. This helped me understand how security analysts use timestamps, authentication events, and command history to investigate activity.

I tried using a python script analyzer to get another and easier way to view the logs. With the script it worked and i got 17 events which are the local test IP. Source IP: 127.0.0.1 Username: root Commands: whoami, ls, uname -a, exit, and the mistyped Swhoami. Failed command: Swhoami

I upgraded the scriptand added Authentication summary: 1 success - 0 failures. Unique source IPs: 1 unique IP, All 17 events came from 127.0.0.1. Command frequency: 5 distinct commands. Session duration: 118.5 seconds. This helps me learn how A SOC analyst would turn raw logs into answers.
