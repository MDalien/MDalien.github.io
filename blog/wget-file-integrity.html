Let's Wget This Bread: Investigating File Changes with auditd

CodePath CYB102 · Linux security lab

For this lab, I explored how Linux Audit (auditd) can help investigate unexpected file modifications. The goal was to monitor protected files, run three provided attack scripts, and use audit logs to connect file changes with recorded processes.

01 — Lab setup

I used an Ubuntu virtual machine with a starter project containing protected files and three attack scripts: attack-a, attack-b, and attack-c. I configured audit rules to monitor write activity against the 10 protected files.

02 — Configuring auditd

I configured file-watch rules using three important options:

  • -w specifies the file to monitor.
  • -p w monitors write activity.
  • -k assigns a key that can be used to filter events.

After loading the rules, I used sudo auditctl -l to verify that the rules were active.

05 — What I learned

This lab gave me practical experience with auditing and investigating file activity on Linux.

  • Audit rules can record write activity involving monitored files.
  • Unique keys make related audit events easier to search.
  • Fields such as name, comm, and exe help connect events to files and processes.
  • Unexpected results should be checked against the original evidence before drawing conclusions.

Conclusion

The exercise showed how file level audit records can support investigation of unexpected changes. It also reinforced that collecting logs is only part of the process: the analyst still needs to go through the evidence and validate the conclusion.
